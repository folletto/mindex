# Setup

Everything that has to be configured by hand — locally, and in the GitHub repository. Nothing here
is needed just to run the app: `npm install && npm run dev` is the whole local setup. The rest
matters when you publish releases, sign builds, or work from a fork.

## Local

**Node 22.** CI pins `node-version: 22` on every job; there is no `engines` field to enforce it
locally, so match it yourself if you hit something odd.

```sh
npm install
npm run dev
```

There is no build step to arrange beyond that:

- **No native rebuild.** `better-sqlite3` ships N-API prebuilds, so there is no `postinstall`
  compile and no Electron headers to fetch — see [architecture.md](architecture.md#the-native-module).
- **No Playwright browser download.** The e2e suite drives the app's own Electron binary, so
  `npx playwright install` is not needed. It does need a build first: `npm run build`, then
  `npm run test:e2e`.

### Environment variables

None are required. These exist for development and for the release workflow:

| Variable | Read by | What it does |
|---|---|---|
| `MINDEX_LIBRARY` | `src/main/index.ts` | Opens this folder as the library instead of the saved one. The e2e tests point it at a temp folder per test. |
| `MINDEX_E2E_PACKAGED` | `tests/e2e/app.spec.ts` | Runs the e2e suite against the installed binary under `release/` rather than `out/`. Fails loudly if there is no packaged build. |
| `ELECTRON_RENDERER_URL` | `src/main/index.ts` | Set automatically by `electron-vite dev`; you do not set this by hand. |

The app itself reads no `.env` file and has no configuration outside the library folder.

## GitHub repository

Two one-time settings, both needed before the release machinery works end to end.

### 1. Pages source

**Settings → Pages → Source: GitHub Actions.** Without it, `pages.yml` fails on its first run. The
download page reads the releases API in the visitor's browser, so it only redeploys when `site/`
itself changes.

### 2. `RELEASE_TOKEN` secret

A personal access token with `contents: write`, added under **Settings → Secrets and variables →
Actions**. GitHub deliberately does not start new workflow runs from events created with the default
`GITHUB_TOKEN`, so without this the version-bump tag is created but `release.yml` never fires.

It is a convenience, not a requirement: you can always run **Release** manually against the tag
instead. `tag.yml` falls back to `GITHUB_TOKEN` and prints a warning saying exactly that.

### 3. Code signing (optional)

Signing is wired up but off, so builds are currently unsigned. Set these repository secrets and
`release.yml` signs and notarizes itself; leave them unset and it produces an unsigned build, which
is fine for a personal tool.

| Secret | For |
|---|---|
| `CSC_LINK` | Certificate (base64 or URL) — macOS and Windows |
| `CSC_KEY_PASSWORD` | Password for that certificate |
| `APPLE_ID` | macOS notarization |
| `APPLE_APP_SPECIFIC_PASSWORD` | macOS notarization |
| `APPLE_TEAM_ID` | macOS notarization |

Note that **macOS auto-update requires a signed app** — which is why Mindex points you at the
download page rather than updating itself. `electron-builder.yml` also sets `identity: null` under
`mac:`; that has to come out before a signed macOS build will actually sign.

`GH_TOKEN` for publishing is the automatic `GITHUB_TOKEN` — nothing to configure.

### If you ever turn on required status checks

`ci.yml` skips documentation-only pull requests via `paths-ignore: ['**.md']`, which is safe today
because `main` has no branch protection and no rulesets. A skipped workflow reports no status at all,
so the moment CI becomes a *required* check, a docs-only PR would sit forever waiting for a run that
never starts. Turning that on means replacing the skip with a filter job that reports success — the
comment at the top of `ci.yml` says the same thing, next to the code.

## Working from a fork

The owner and repo name are hardcoded in four places. Change all of them or the download page will
list someone else's releases:

| Where | What |
|---|---|
| `electron-builder.yml` | `publish.owner` / `publish.repo`, plus `appId` and `copyright` |
| `site/index.html` | the `REPO` constant (`'folletto/mindex'`) |
| `README.md` | the Download and Releases links at the top |
| `docs/*.md` | any links back to the repository |

## Regenerating the icon

`build/icon.png` is committed, and `electron-builder` derives the `.icns` and `.ico` from it at
package time. It is generated by a script rather than exported from a design tool, so it stays
reviewable:

```sh
node scripts/make-icon.mjs
```

This is not wired into the build — run it and commit the result when the icon changes.
